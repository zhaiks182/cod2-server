# CoD2 Dedicated Server (Linux) — Install Guide + Mod ZPAM 4.08 Custom (Score Popup + Blood FX)

*[Leer en español](README.md)*

Complete guide to standing up a **Call of Duty 2** dedicated server on Linux
(Ubuntu) using `cod2_lnxded` + `libcod`, running as a systemd service, with
the **zPAM 4.08** mod and two custom features (score popup + blood FX) added
on top of the original mod.

Tested on: **Ubuntu 24.04 LTS**, `amd64` architecture with `i386` support.

## 1. System prerequisites

`cod2_lnxded` is a 32-bit binary, so on a modern `amd64` system you need to
enable the `i386` architecture before installing its dependencies.

### 1.1. CoD2 prerequisites

```bash
sudo dpkg --add-architecture i386
sudo apt-get update
sudo apt-get -y install libstdc++5:i386
```

### 1.2. libcod prerequisites

[`libcod`](https://github.com/xtnded/libcod) (here in its `libCoD2x.so` fork,
loaded via `LD_PRELOAD`) extends the server with more console
commands/cvars and support for mods like zPAM. The already-compiled binary
(`libCoD2x.so`) is included in this repo (section 3.1) — you still need
these 32-bit libraries to run it:

```bash
sudo apt-get -y install gcc-multilib
sudo apt-get -y install libmysqlclient-dev:i386
sudo apt-get -y install g++-multilib
```

## 2. Server file layout

The whole server lives under a single `fs_homepath`. On the reference server
used to write this guide it's this path, but **you can clone the repo into
any folder** — `start_libcod.sh` auto-detects its own location (section 4),
only the systemd unit needs the real path written in by hand (section 5):

```
/home/gameserver/1.3/puG/
├── cod2_lnxded              # Dedicated server binary (32-bit)
├── libCoD2x.so               # libcod, loaded via LD_PRELOAD
├── start_libcod.sh           # Startup script
├── start_server.sh           # Old wrapper (screen) - unused, systemd replaces it
└── main/                     # "base" fs_game (game assets + mod)
    ├── iw_00.iwd ... iw_15.iwd                # Base game assets (~1.9 GB)
    ├── localized_english_iw00.iwd ... iw11.iwd # EN localization
    ├── iw_CoD2x_01.iwd                         # libcod/CoD2x assets
    ├── zpam_maps_v7.iwd                        # Mod map pack
    ├── zpam408.iwd                             # zPAM 4.08 mod (+ custom features, see section 7)
    ├── server.cfg                              # Server config (gametype, rcon, zPAM cvars)
    ├── config_mp_server.cfg                    # Engine-autogenerated config (don't edit by hand)
    └── games_mp.log                            # Match event log (kills, connections, etc.)
```

Notes:

- The `iw_XX.iwd` and `localized_english_iw*.iwd` files are the original
  game assets (not included in this setup — they're Activision's property,
  you need to copy them from a legitimate CoD2 installation, see section 3).
- `main/` acts as both `fs_basepath`/`fs_game` in this setup (`fs_game` is
  empty in `start_libcod.sh`, see next section): everything lives at the
  root of `main/`.
- `sv_wwwBaseURL` in `server.cfg` points to your own HTTP server
  (`http://<ip>/cod2/`) so clients download `zpam_maps_v7.iwd` and
  `zpam408.iwd` without saturating the game server's bandwidth.

## 3. Files to prepare: repo-provided vs. copied over FTP

To stand up the server you need two distinct groups of files: the ones this
repo provides (binary, mod, maps, config), obtained by downloading a `.zip`
or with `git clone` (section 3.1), and the original base game assets, which
you have to copy separately from your own CoD2 installation (section 3.2).

### 3.1. Downloading the setup files

This repo includes everything needed except the base game assets:

| File | What it is |
|---|---|
| `cod2_lnxded` | Dedicated server binary (headless) |
| `libCoD2x.so` | libcod, loaded via `LD_PRELOAD` (section 1.2) |
| `start_libcod.sh` | Startup script (section 4) |
| `main/server.cfg` | Own config (gametype, rcon, zPAM cvars) |
| `main/zpam408.iwd` | Mod, with the custom features (section 7) |
| `main/zpam_maps_v7.iwd` | Official mod map pack (~178 MB) |

There are two ways to get them:

#### Option A (recommended): download the Release `.zip`

Doesn't need git or Git LFS — the simplest way if you're standing up the
server just once:

```bash
wget https://github.com/zhaiks182/cod2-server/releases/latest/download/zpam408-popup-blood.zip
unzip zpam408-popup-blood.zip -d cod2-server
```

That leaves you with a `cod2-server/` folder matching the layout from
section 2 (`cod2_lnxded`, `libCoD2x.so`, `start_libcod.sh`, `main/...`),
ready to copy as-is to the server.

#### Option B: clone the repo with `git`

Useful if you later want to update with `git pull` instead of
re-downloading everything. `main/zpam_maps_v7.iwd` is over 100 MB, so the
repo uses **[Git LFS](https://git-lfs.com/)** — install it before cloning
(one time per machine):

```bash
# Debian/Ubuntu
sudo apt-get install git-lfs
git lfs install

git clone https://github.com/zhaiks182/cod2-server.git
```

> ⚠️ If you skip the `git-lfs` step, `clone` "works" without erroring, but
> the large files come out as ~130-byte text pointers instead of the real
> content — the server won't start. Also, GitHub LFS on free accounts has a
> **1 GB/month bandwidth quota**: since `zpam_maps_v7.iwd` is ~178 MB, that's
> only good for 5-6 `git clone`s before GitHub starts rejecting LFS
> downloads until the following month. That's why Option A is recommended
> for most cases — it doesn't consume that quota.

### 3.2. Files you copy over FTP from your CoD2 installation

The base game assets (`iw_00.iwd` … `iw_15.iwd`,
`localized_english_iw*.iwd`) are Activision's property and weigh ~1.9 GB in
total — they don't come with this repo, you need to copy them from your own
legitimate CoD2 installation (`main/` folder of the original game) directly
into the server's `main/` folder, **at the same level** as `server.cfg` and
`zpam408.iwd`:

- `iw_00.iwd` … `iw_15.iwd`
- `localized_english_iw00.iwd` … `localized_english_iw11.iwd`
- `iw_CoD2x_01.iwd` (comes with libcod)

Use an FTP/SFTP client (FileZilla, WinSCP, etc.) pointed at the server's IP,
connecting over SFTP with the same SSH key/user you already have set up,
and upload those files into the `main/` folder inside wherever you deployed
the repo (section 3.1).

## 4. Startup script (`start_libcod.sh`)

`start_libcod.sh` (at the root of the repo/cloned folder):

```bash
#!/bin/bash

# Auto-detect the folder this script lives in, so it works regardless of
# where the repo was cloned/copied to (no hardcoded path).
DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

sv_maxclients="30"
#fs_game="dtNriflesDM"
fs_homepath="$DIR"
cod="$DIR/cod2_lnxded"
com_hunkMegs="256"
config="server.cfg"
cracked="1"
net_port="28960"


args=\
"+set fs_homepath \"$fs_homepath\" "\
"+set sv_cracked $cracked "\
"+set fs_game $fs_game "\
"+set net_port $net_port "\
"+set com_hunkMegs $com_hunkMegs "\
"+set sv_maxclients $sv_maxclients "\
"+set fs_basepath \"$fs_homepath\" "\
"+exec $config"

LD_PRELOAD="$DIR/libCoD2x.so" $cod $args +set g_gametype sd +map mp_toujane_fix +set rcon_password pug2026! +map_rotate
```

Key points:

- **No hardcoded paths**: `DIR` is computed from the script's own location
  (`dirname`), so it runs the same no matter which folder you cloned/copied
  the repo into — nothing to edit here even if you're not using
  `/home/gameserver/1.3/puG`.
- `LD_PRELOAD` is what injects `libCoD2x.so` into the server process —
  without this, zPAM doesn't work (it uses the extended commands/cvars that
  libcod adds).
- `fs_game` is left empty (commented out above) — all content (mod
  included) is served from `main/`, not a separate mod folder.
- `sv_cracked "1"` is required to run the binary without the original
  Steam/CD-key launcher.
- The initial map/gametype and `rcon_password` are passed as extra
  arguments at the end; `+map_rotate` starts the rotation defined in
  `server.cfg`.

Give it execute permission (replace the path with wherever you
cloned/copied the repo):

```bash
chmod +x /path/where/you/cloned/the/repo/start_libcod.sh
```

## 5. systemd service

So the server starts automatically on VM boot and restarts if it crashes.

Unlike `start_libcod.sh` (which auto-detects), the systemd unit does need
the absolute path written in by hand — replace
`/path/where/you/cloned/the/repo` with the real path on your server.

### 5.1. Create the service file

```bash
sudo nano /etc/systemd/system/cod2server.service
```

Contents:

```ini
[Unit]
Description=Call of Duty 2 Dedicated Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/path/where/you/cloned/the/repo
Nice=-20
ExecStart=/bin/bash /path/where/you/cloned/the/repo/start_libcod.sh
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

Save in nano: `Ctrl + O` → `Enter` → `Ctrl + X`.

> `Nice=-20` gives the process the highest CPU priority (valid range -20 to
> 19, lower = higher priority; -20 is the ceiling). Useful on shared VMs to
> minimize server-tick lag.

### 5.2. Reload systemd

```bash
sudo systemctl daemon-reload
```

### 5.3. Enable automatic startup

```bash
sudo systemctl enable cod2server.service
```

### 5.4. Start / restart the server

```bash
sudo systemctl restart cod2server.service
```

### 5.5. Check status

```bash
sudo systemctl status cod2server.service
```

It should look something like this:

```
● cod2server.service - Call of Duty 2 Dedicated Server
     Loaded: loaded (/etc/systemd/system/cod2server.service; enabled; preset: enabled)
     Active: active (running) since ...
   Main PID: 677 (bash)
     CGroup: /system.slice/cod2server.service
             ├─677 /bin/bash /home/gameserver/1.3/puG/start_libcod.sh
             └─680 /home/gameserver/1.3/puG/cod2_lnxded ...
```

To watch the logs live (kills, connections, rcon commands):

```bash
sudo journalctl -u cod2server.service -f
```

## 6. Basic configuration (`server.cfg`)

`main/server.cfg` is where the gametype/mode/zPAM cvar configuration lives.
It's referenced from `start_libcod.sh` via `+exec server.cfg`. Minimal
relevant example:

```c
// Gametype: sd, dm, tdm, hq, ctf, htf, re, strat
set g_gametype "sd"

// zPAM mode (pub | comp | comp_mr3 | comp_2v2 | comp_rifle | comp_lan | ...)
set pam_mode "comp_na"

set sv_hostname "My CoD2 server"
set scr_motd "Welcome. This server is running zPAM 4.08"

set g_password ""          // server password (empty = public)
set rcon_password ""       // remote admin password - do NOT leave empty in production

// Download maps/mod over HTTP instead of the game protocol (much faster)
seta sv_wwwBaseURL "http://<YOUR_IP>/cod2/"
seta sv_wwwDownload "1"
seta sv_wwwDlDisconnected "0"
```

> ⚠️ **Security**: change `rcon_password` to something unique before
> exposing the server to the internet — with rcon an attacker can run any
> console command on the server (kick, ban, change cvars, etc.).

For the HTTP download (`sv_wwwBaseURL`) to work, `zpam_maps_v7.iwd` and
`zpam408.iwd` need to be served from a webserver (nginx/apache) at the
`/cod2/` path on that IP — not covered in this guide.

## 7. Mod ZPAM 4.08 — Custom Features (Score Popup + Blood FX)

Built on top of the [zPAM 4.08](https://github.com/eyza-cod2/zpam3) mod
(`zpam408.iwd`), two additional features were integrated without touching
the mod's original event/scoring system.

### 7.1. Mod context

- CoD2 dedicated server (Linux, `cod2_lnxded` + `libcod`), gametypes: `sd`, `dm`, `tdm`,
  `ctf`, `hq`, `htf`, `re`, `strat`.
- Modular architecture: each feature lives in `maps/mp/gametypes/_<name>.gsc` with an
  `init()` function, threaded once from
  `maps/mp/gametypes/global/_init.gsc :: InitModules()`.
- **Own event system** (`maps/mp/gametypes/global/events.gsc`): instead of overriding
  `_callbacksetup.gsc` (which centralizes hitbox/damage/logging fixes for the whole mod),
  modules subscribe with `addEventListener("onXxx", ::handler)`. Relevant events:
  `onPlayerDamaged`, `onPlayerKilled`, `onCvarChanged`.
- **Cvars**: registered with `registerCvar(name, type, default)` /
  `registerCvarEx(method, name, type, default, min, max)`
  (`maps/mp/gametypes/global/cvar_system.gsc`). For `level.<cvar>` to be populated you
  need to register an `onCvarChanged` listener **before** calling `registerCvar` (the
  registration fires the event once with `isRegisterTime=true`).
- **Per-gametype rules** (`maps/mp/gametypes/rules/<gametype>/<comp|pub>.gsc`): define
  default cvar values via `ruleCvarDefault(arr, "cvar", value)`. Optional —
  `registerCvar` already ships its own hardcoded default — only needed if you want a
  different value per mode/gametype.
- **Deploy without repacking**: CoD2 prioritizes loose `.gsc`/asset files in the server's
  `fs_game` over what's packaged in the `.iwd`. You can iterate fast with loose files
  and, once tested, merge them into the `.iwd` (with
  `System.IO.Compression.ZipFile` in `Update` mode: `entry.Delete()` + `CreateEntry()`).

Real kill callback (`_callbacksetup.gsc :: CodeCallback_PlayerKilled`), exact order:
`notifyKilling` (can cancel the kill) → `notifyKilled` (fires all `onPlayerKilled`
listeners, ours included) → `level.onAfterPlayerKilled`
(gametype-specific: this is where ZPAM actually assigns
`attacker.score = attacker.pers["score"]`, the real persistent value).

> ⚠️ There was an **old/unused** loose `_callbacksetup.gsc`, from a simpler mod (with
> an airstrike addon), that would completely override ZPAM's real callback if it ended
> up in `fs_game`. It was left untouched/undeleted because the user confirmed it isn't
> deployed, but if a running `_callbacksetup.gsc` ever shows up WITHOUT the event
> system (`level.events`), that's a sign that old file is being used by mistake —
> it silently breaks dozens of ZPAM modules.

### 7.2. Score Popup (`+1` / `+2` / red team-kill)

Based on: https://killtube.org/showthread.php?1208-plusscore (standalone script, not
integrated into any framework — doesn't apply as-is when packaged inside a mod with its
own scoring system, see compatibility note below).

#### Files touched inside `zpam408.iwd`

- **`maps/mp/gametypes/_scorepopup.gsc`** (new) — the complete module.
- **`maps/mp/gametypes/global/_init.gsc`** — 1 line added to `InitModules()`:
  `thread maps\mp\gametypes\_scorepopup::init();`
- **`maps/mp/gametypes/rules/sd/comp.gsc`** — 1 line added (optional, default already
  comes from the module):
  `arr = ruleCvarDefault(arr, "scr_scorepopup", 1);`

#### Cvar

`scr_scorepopup` (BOOL, default `1`) — hot-toggleable via rcon, without restarting the
map (`level.scr_scorepopup` is checked on every kill, not just at registration).

#### Behavior

- HUD element centered above the crosshair, with a scale/opacity animation (grows and
  fades).
- `+1` normal kill · `+2` headshot or melee · red and negative on team-kill.
- Skipped during `level.in_readyup` (doesn't show a fake score when it wouldn't actually
  count) and in the `strat` gametype (no individual score there).
- ZPAM already promotes `sMeansOfDeath` to `"MOD_HEAD_SHOT"` for headshots (except with
  a shotgun) in `_callbacksetup.gsc :: CodeCallback_PlayerKilled()`, **before** this
  event fires — the module just reads that classification, doesn't recompute it.

#### ⚠️ Scoring compatibility note (important if reused in another mod)

The original script does `attacker.score += score` with its own bonus math. In ZPAM
this is **harmless but inert**: every gametype (`sd.gsc`, `dm.gsc`, `tdm.gsc`, etc.)
unconditionally overwrites `attacker.score = attacker.pers["score"]` in
`onAfterPlayerKilled()`, which runs **after** our `onPlayerKilled` listener (see the
callback order above) — so whatever value the popup sets on `.score` gets overwritten
in the same server frame, before the client ever sees it. If you port this module to a
mod WITHOUT that unconditional `.score` overwrite, you need to remove the
`attacker.score += score;` line or you'll double the real score.

#### Full code

```c
#include maps\mp\gametypes\global\_global;

/*
	Score popup ("+1", "+2" on headshot/melee, red negative on team-kill) shown
	above the crosshair on kill.

	Based on: https://killtube.org/showthread.php?1208-plusscore

	Integrated into ZPAM:
		- Hooked through ZPAM's own event system (onPlayerKilled), instead of
		  overriding _callbacksetup.gsc directly, so all of ZPAM's hitbox/damage/
		  logging code keeps working untouched.
		- Toggleable per server via cvar scr_scorepopup (BOOL, default 1).
		- attacker.score is still touched here (kept from the original script,
		  same +1/+2/team-kill math) but this has no lasting effect on the real
		  scoreboard: every gametype's onAfterPlayerKilled() runs right after this
		  event and unconditionally overwrites .score from attacker.pers["score"]
		  (the value ZPAM actually tracks/persists). So this module is purely a
		  visual layer and can never desync the real score.
*/

init()
{
	// No individual kill score concept in strat
	if (level.gametype == "strat")
		return;

	addEventListener("onCvarChanged", ::onCvarChanged);

	registerCvar("scr_scorepopup", "BOOL", 1); // level.scr_scorepopup

	if (game["firstInit"])
	{
		precacheString(&"");
		precacheString(&"+");
	}

	addEventListener("onPlayerKilled", ::onPlayerKilled);
}

// This function is called when cvar changes value.
// Is also called when cvar is registered
// Return true if cvar was handled here, otherwise false
onCvarChanged(cvar, value, isRegisterTime)
{
	switch (cvar)
	{
		case "scr_scorepopup":
			level.scr_scorepopup = value;
			return true;
	}
	return false;
}

// self = victim (game engine convention for CodeCallback_PlayerKilled)
onPlayerKilled(eInflictor, eAttacker, iDamage, sMeansOfDeath, sWeapon, vDir, sHitLoc, timeOffset, deathAnimDuration)
{
	if (level.scr_scorepopup == 0)
		return;

	// No real score change happens during ready-up practice - don't show a fake one
	if (level.in_readyup)
		return;

	attacker = eAttacker;
	victim = self;

	if (!isDefined(attacker) || !isDefined(victim))
		return;
	else if (!isPlayer(attacker) || !isPlayer(victim))
		return;
	else if (attacker == victim)
		return;

	score = 1;

	// ZPAM already promotes sMeansOfDeath to "MOD_HEAD_SHOT" for head hits (except
	// shotgun) in _callbacksetup.gsc :: CodeCallback_PlayerKilled(), before this
	// event fires - so we just read the classification ZPAM already computed.
	if (isDefined(sMeansOfDeath))
	{
		if (sMeansOfDeath == "MOD_HEAD_SHOT")
			score = 2;
		else if (sMeansOfDeath == "MOD_MELEE")
			score = 2;
	}

	if (isDefined(attacker.pers["team"]) &&
		isDefined(victim.pers["team"]) &&
		attacker.pers["team"] == victim.pers["team"] &&
		level.gametype != "dm")
	{
		score *= -1;
	}

	if (score < 0) score += 1;
	else                 score -= 1;

	attacker.score += score;

	attacker thread plusscore(score + 1);
}


plusscore(score)
{
	if (!isplayer(self))
		return;

	if (!isdefined(self.izno_plusscore)) // first run
	{
		self.izno_plusscore = newClientHudElem2(self);
		self.izno_plusscore.instance = 0;
		self.izno_plusscore.score = score;
		self.izno_plusscore.horzAlign = "center";
		self.izno_plusscore.vertAlign = "middle";
		self.izno_plusscore.alignX = "center";
		self.izno_plusscore.alignY = "middle";
		self.izno_plusscore.x = 0; // middle of screen
		self.izno_plusscore.y = -40; // just above middle of screen
		self.izno_plusscore.alpha = 0.3;
		self.izno_plusscore.fontscale = 0.5;
	}
	else // not first-run
	{
		if (self.izno_plusscore.alpha < 0.3 || self.izno_plusscore.score == 0)
			self.izno_plusscore.alpha = 0.3;
		if (self.izno_plusscore.fontscale < 0.5 || self.izno_plusscore.score == 0)
			self.izno_plusscore.fontscale = 0.5;
		self.izno_plusscore.instance++;
		self.izno_plusscore.score += score;
	}
	if (self.izno_plusscore.score < 0)
	{
		self.izno_plusscore.color = (235/255, 10/255, 10/255); // negative scores are red
		self.izno_plusscore.label = &"";
	}
	else
	{
		self.izno_plusscore.color = (1, 230/255, 125/255); // yellow-ish
		self.izno_plusscore.label = &"+";
	}
	self.izno_plusscore setvalue(self.izno_plusscore.score);

	current_instance = self.izno_plusscore.instance;
	make_bigger = true;
	more_opaque = true;
	steady_opaque_timer = 0;
	alpha_done = false;
	size_done = false;
	while (isdefined(self) && current_instance == self.izno_plusscore.instance && !(alpha_done && size_done))
	{
		if (make_bigger && self.izno_plusscore.fontscale < 2)
			self.izno_plusscore.fontscale += 0.35;
		else if (make_bigger)
			make_bigger = false;
		else if (self.izno_plusscore.fontscale > 2)
			self.izno_plusscore.fontscale -= 0.2;
		else
		{
			size_done = true;
			self.izno_plusscore.fontscale = 1.5;
		}

		if (more_opaque && self.izno_plusscore.alpha <= 0.9) // dont overflow this
			self.izno_plusscore.alpha += 0.1;
		else if (more_opaque && steady_opaque_timer == 20)
			more_opaque = false;
		else if (more_opaque)
			steady_opaque_timer++;
		else if (self.izno_plusscore.alpha >= 0.1) // dont underflow this
			self.izno_plusscore.alpha -= 0.1;
		else
		{
			alpha_done = true;
			self.izno_plusscore.alpha = 0;
		}
		wait 0.05;
	}
	if (!isdefined(self))
		return;
	if (current_instance == self.izno_plusscore.instance)
	{
		wait 0.5;
		if (isdefined(self) && self.izno_plusscore.instance == current_instance)
			self.izno_plusscore.score = 0;
	}
}
```

### 7.3. Blood FX (impact spray + ground "pool")

Source assets: `iw_blood.iwd` pack (only contained `.efx` files, **no script at all** —
`fx/impacts/flesh_hit.efx` and 6 effects in `fx/effects/gore/`:
`splats`, `stains`, `stains_lg`, `stains2`, `stains2_lg`, `stains2_big`).

#### Key finding

Searched `loadfx|playfx|_effect\[` across **the whole mod** (every `.gsc`, every
`maps/mp/mp_<map>_fx.gsc`) and found no reference to these assets — not even to
`flesh_hit.efx`, which ZPAM already shipped packaged. In other words, they were in the
`.iwd` but **nobody was calling them**. In CoD2, particle effects (`fx`) don't trigger
on their own by naming convention — you need `loadfx()` at precache time and `playfx()`
at the right moment, exactly like every `mp_<map>_fx.gsc` does with its own map effects
(real example taken from `mp_carentan_fx.gsc`):


#### Behavior

- **`onPlayerDamaged`**: on every bullet/melee impact (`vPoint`/`vDir` defined, and
  `sMeansOfDeath` is `MOD_PISTOL_BULLET`/`MOD_RIFLE_BULLET`/`MOD_MELEE`), triggers

- **`onPlayerKilled`**: randomly picks one of the 6 `gore/` effects and triggers it on
  the ground, at the body's position (`self.origin`, captured **before** threading,
  since the player can respawn and move).

#### ⚠️ Known limitation: the "pool" isn't a persistent decal

The `.efx` files in `gore/` are very small binaries (240–290 bytes) → short particle
bursts (1-2 seconds), **not persistent decals**. In CoD2, marks that actually "stick"
to the floor/wall (e.g., bullet holes) use the engine's **decal** system, which is
separate from the `fx` particle system and has no GSC command exposed to trigger it
manually — you can only replay what the `.efx` itself already defines (you can't
"extend" its internal duration from script without editing the binary with a tool like
the IW Effects Editor).

**Workaround applied** (not a real decal, but disguises the cutoff): instead of a
single `playfx`, the same effect is re-triggered at the same point every 1.5s for 15s
(`bloodPoolPersist()`), running in a `level` thread (not `self`) so it doesn't depend on
the player staying alive/connected.

#### Another limitation NOT related to the script: the corpse disappears

Confirmed through exhaustive search that **no ZPAM `.gsc` removes or hides the body**
of a dead player. Two valid explanations, depending on the testing context:

1. **Gametypes with fast respawn (dm/tdm/etc.) or readyup/warmup**: the corpse is the
   same entity as the player — when that player respawns, the entity moves to the
   spawn point and the body "disappears" from where it died. This is true in any CoD
   mod, can't be avoided by script.
2. **SD with a round in progress, many bots dying fast**: most likely a native engine
   limit (inherited from idTech3) on the maximum number of simultaneous rendered
   corpses — once exceeded, the oldest gets recycled. Also not controllable from
   `.gsc`.

#### Full code

```c
#include maps\mp\gametypes\global\_global;

/*
	Blood impact spray (on hit) + ground stain (on kill), using the "iw_blood" fx pack:
		fx/impacts/flesh_hit.efx
		fx/effects/gore/splats.efx, stains.efx, stains_lg.efx, stains2.efx, stains2_lg.efx, stains2_big.efx

	Nothing in ZPAM called loadfx()/playfx() for these assets before - the files just sat
	in the iwd unused. This module is what actually triggers them, the same way every
	maps\mp\mp_<map>_fx.gsc precaches and plays its own map effects.
*/

init()
{
	addEventListener("onCvarChanged", ::onCvarChanged);

	registerCvar("scr_blood", "BOOL", 1); // level.scr_blood

	level._effect["flesh_hit"]         = loadfx("fx/impacts/flesh_hit.efx");
	level._effect["blood_splats"]      = loadfx("fx/effects/gore/splats.efx");
	level._effect["blood_stains"]      = loadfx("fx/effects/gore/stains.efx");
	level._effect["blood_stains_lg"]   = loadfx("fx/effects/gore/stains_lg.efx");
	level._effect["blood_stains2"]     = loadfx("fx/effects/gore/stains2.efx");
	level._effect["blood_stains2_lg"]  = loadfx("fx/effects/gore/stains2_lg.efx");
	level._effect["blood_stains2_big"] = loadfx("fx/effects/gore/stains2_big.efx");

	addEventListener("onPlayerDamaged", ::onPlayerDamaged);
	addEventListener("onPlayerKilled", ::onPlayerKilled);
}

// This function is called when cvar changes value.
// Is also called when cvar is registered
// Return true if cvar was handled here, otherwise false
onCvarChanged(cvar, value, isRegisterTime)
{
	switch (cvar)
	{
		case "scr_blood":
			level.scr_blood = value;
			return true;
	}
	return false;
}

// self = victim (game engine convention for CodeCallback_PlayerDamage)
onPlayerDamaged(eInflictor, eAttacker, iDamage, iDFlags, sMeansOfDeath, sWeapon, vPoint, vDir, sHitLoc, timeOffset)
{
	if (level.scr_blood == 0)
		return;

	if (!isDefined(vPoint) || !isDefined(vDir))
		return;

	// Only actual weapon/melee hits on flesh (skip suicide/grenade-splash-only edge cases without a clean hit point)
	if (sMeansOfDeath != "MOD_PISTOL_BULLET" && sMeansOfDeath != "MOD_RIFLE_BULLET" && sMeansOfDeath != "MOD_MELEE")
		return;

	playfx(level._effect["flesh_hit"], vPoint, vDir);
}

// self = victim (game engine convention for CodeCallback_PlayerKilled)
onPlayerKilled(eInflictor, eAttacker, iDamage, sMeansOfDeath, sWeapon, vDir, sHitLoc, timeOffset, deathAnimDuration)
{
	if (level.scr_blood == 0)
		return;

	pool = pickBloodPool();
	origin = self.origin; // capture now - self (the player) will move away once respawned

	// The .efx itself is a short one-shot spray, not a persistent decal - re-trigger it
	// at the same spot for a while to fake a lasting pool on the ground.
	level thread bloodPoolPersist(pool, origin);
}

bloodPoolPersist(pool, origin)
{
	duration = 15; // seconds - tune this if it looks too short/long or costs too much perf
	interval = 1.5;

	for (elapsed = 0; elapsed < duration; elapsed += interval)
	{
		playfx(level._effect[pool], origin, (0, 0, 1));
		wait interval;
	}
}

pickBloodPool()
{
	pools = [];
	pools[pools.size] = "blood_splats";
	pools[pools.size] = "blood_stains";
	pools[pools.size] = "blood_stains_lg";
	pools[pools.size] = "blood_stains2";
	pools[pools.size] = "blood_stains2_lg";
	pools[pools.size] = "blood_stains2_big";

	return pools[randomint(pools.size)];
}
```
